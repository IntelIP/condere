# Application discovery (T8)

Read the T8 contract and the brief. Proposed applications are hypotheses until
customer evidence supports them; Market work tests them later.

Method:

1. Map what the code demonstrably does (implemented capabilities, integrations,
   performance-relevant design) to workloads it could serve.
2. Read examples, demos and documented use cases; separate vendor claims from
   adopters' own descriptions.
3. Search for how existing users apply the technology and where they hit limits.
4. Name workloads the evidence shows it is unsuitable for.

Fill `applications`, `target_workloads`, `adjacent_uses` and `unsuitable_uses`.
Tie each application to a cited capability. Preserve the founder's stated idea,
but do not treat it as demand.
